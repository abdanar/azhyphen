\textsf{azhyphen} provides standalone Azerbaijani hyphenation for LuaLaTeX
and XeLaTeX. It uses pre-generated patterns; document compilation never runs
\texttt{PATGEN}. The source distribution includes the public annotated data
and generator needed to reproduce the patterns. Linguistic coverage remains
experimental.

\section{Usage}
Load the package and use a font that includes Azerbaijani characters:
\begin{verbatim}
\documentclass{article}
\usepackage{fontspec}
\setmainfont{CMU Serif}
\usepackage{azhyphen}
\begin{document}
Azərbaycan dilində mətn avtomatik olaraq hecalanır.
\end{document}
\end{verbatim}
Compile with \texttt{lualatex} or \texttt{xelatex}; pdfLaTeX is unsupported.
CMU Serif comes from TeX Live's \texttt{cm-unicode} package.
Loading \textsf{azhyphen} activates Azerbaijani globally,
with distinct dotted i/İ and dotless ı/I mappings. No package options,
Babel or Polyglossia setup are needed.

Breaks leave at least two letters on each side (provisional minima 2/2).
For corrections, use \verb|\hyphenation{...}| after loading the package or
insert \verb|\-| in the text. Review important typography manually;
actual line breaks also depend on the font, line width and context.

To inspect permitted breaks in the log, use \verb|\showhyphens{fotoelektrik}|.

\section{Installation}
Install manually from a GitHub source checkout or source ZIP:
\url{https://github.com/abdanar/azhyphen}.

For source installation, use Python 3.10 or newer and TeX Live with LuaLaTeX,
XeLaTeX, \texttt{iftex}, \texttt{luaotfload} and \texttt{fontspec}.
From the checkout or extracted archive, run:
\begin{verbatim}
python scripts/azhyphen.py install
\end{verbatim}
The installer uses your user TeX tree and registers Azerbaijani in the
XeLaTeX user format, without administrator access. Repeat installation
after updating patterns.

To remove the installation, run:
\begin{verbatim}
python scripts/azhyphen.py uninstall
\end{verbatim}
Uninstallation removes marked registrations and unmodified package files;
modified files and unrelated registrations are preserved. GNU Make aliases:
\texttt{make install} and \texttt{make uninstall}.

For an unregistered XeLaTeX language, rerun installation using the same user
TeX tree as compilation. Repair missing unrelated language files in your
TeX installation before retrying.

\section{Hyphenation data and quality}
The 303 hyphenation patterns are generated reproducibly with \texttt{PATGEN}
from 2,007 annotated training words, starting from empty patterns.
The 263 words in the public evaluation set are excluded from training.

On this evaluation set, the patterns achieve \textbf{81.75\% exact-word
accuracy} and \textbf{95.65\% breakpoint F1} (97.74\% precision,
93.65\% recall): 605 correct, 14 incorrect and 41 missed breakpoints.
Scores compare permitted breaks with complete annotations, including
breaks suppressed by the provisional minima.

These measurements describe the public evaluation set, not all Azerbaijani
vocabulary. Repeated development against this set does not give an unbiased
estimate for unseen words. Names, compounds and other unfamiliar words may
need manual correction. The README records the generation parameters and
current evaluation statistics.

\section{Contributing}
To add or correct an annotated word in a GitHub source checkout:
\begin{enumerate}
  \setlength{\itemsep}{0pt}
  \setlength{\parskip}{0pt}
  \item Edit \path{data/hyphenated.txt}.
  \item Run \texttt{make update}.
  \item Run \texttt{make test}.
  \item Submit the source and generated changes, with evidence for corrections.
\end{enumerate}
Use UTF-8, one NFC Azerbaijani word per line, with ASCII \texttt{-} marking
each reviewed syllable boundary. Blank lines, comments and duplicate words
are rejected. Contributions to the word lists must use the same CC0 terms.

\path{data/evaluation.txt} is a separate public evaluation set. Do not move
its words into training or adjust annotations to match predictions.
Corrections to it need independent linguistic evidence.

Development requires Python 3.10 or newer, GNU Make and TeX Live with
\texttt{patgen}; tests remain in the GitHub repository. \texttt{make update}
regenerates patterns, derived files and the README quality summary;
\texttt{make test} runs maintenance and engine tests. \texttt{make check}
detects stale generated files, and \texttt{make doc} builds the user manual.
See the README for details.
